# Dedicated Browser Setup

Use a separate browser profile for parent portals so that school sessions, downloads, autofill, and bookmarks do not mix with a parent’s everyday browsing.

## Consent boundary

Creating a profile changes local browser state. Before creating one, ask for the parent’s explicit approval unless they already asked to set it up. The parent—not the agent—enters passwords, OTPs, recovery codes, or payment details.

## Setup procedure

1. Inspect whether the portal is already open in a dedicated profile. Reuse it if its intended institution and parent account can be verified.
2. If no dedicated profile exists, offer to create one named `Parent Portal` or a parent-selected neutral name. Do not use a child’s full name in the profile name.
3. Create a new browser profile with a separate local profile directory. Do not clone the parent’s default profile, import browser data, or enable sync by default.
4. Open only the requested parent portal in that profile. Stop at the sign-in screen and let the parent enter credentials and complete MFA themselves.
5. After the parent finishes, verify only visible, non-secret evidence: the expected institution, child/classroom context, and notice area. Do not read, copy, or report account identifiers.
6. Keep this profile limited to parent portals. Do not open banking, personal email, shopping, social media, or unrelated accounts in it.

## Browser-specific guidance

- **Chrome / Edge:** Use the profile picker to add a profile; choose a local profile unless the parent explicitly wants browser sync. Give it a neutral name and an easily distinguishable color/icon.
- **Safari:** Prefer a dedicated Safari Profile, with separate history, extensions, tab groups, and website data. The parent should complete sign-in in that profile.
- **Firefox:** Create a separate profile through Firefox’s profile manager. Do not copy the default profile’s cookies or saved logins.

Exact labels change by browser version. Use the visible profile manager rather than assuming a menu path.

## Verification checklist

- [ ] The parent approved creation or reuse of a dedicated profile.
- [ ] The profile is separate from the default browser profile.
- [ ] No credentials, OTPs, cookies, or saved-login contents were exposed to the agent.
- [ ] The parent completed login and MFA directly.
- [ ] The expected institution and parent notice context are visible.
- [ ] The profile is not being used for unrelated sensitive sites.
